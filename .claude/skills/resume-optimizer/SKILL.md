# 简历优化（STAR 原则）

把平淡的经历描述改写成结构化、可量化、突出个人贡献的 STAR 表述。

## STAR 拆解

每个经历按四段组织：

- **S（Situation 情境）**：当时所处的背景与问题。
- **T（Task 任务）**：需要达成的目标或职责。
- **A（Action 行动）**：本人具体做了什么（强调「我」的动作）。
- **R（Result 结果）**：带来的可量化成果（数字、百分比、时间、规模）。

## 改写流程

1. 从用户提供的信息中提取：角色、项目 / 工作背景、负责事项、产出。
2. 缺失字段（如无量化结果）先向用户追问，而不是编造数字。
3. 用动词开头的主动语态写「行动」，用数字写「结果」。

## 结构化字段

技能、工作经历、项目经历各自的最小字段见 `references/star-template.md`。

## 示例

**Example 1:**
Input: 负责公司后台管理系统开发，写接口和页面。
Output:
- 情境 / 任务：公司后台系统接口分散、页面开发效率低。
- 行动：主导重构后台管理系统，将 40+ 接口统一为三层架构（控制器 - 服务 - 数据访问），引入 TypeScript 严格模式与参数校验。
- 结果：接口平均响应时间降低 30%，新功能开发周期从 3 天缩短到 1.5 天。

## 输出约定

用 Markdown 输出，每个经历一段，用 `- **情境**：... / - **任务**：... / - **行动**：... / - **结果**：...` 的列表，或按 `references/star-template.md` 的表单结构。保持数字真实，不虚构。
