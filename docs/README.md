# my-pc 项目解决方案

> 本目录是从 `project-plan.md` 需求清单展开的**可执行解决方案**。它把「做什么」变成「怎么做」，供开发者（或 AI 编码代理）按序落地。纯文档，不含实现代码。

## 1. 项目定位

my-pc 是一款 **Electron 桌面应用**，面向个人电脑的「运维 + 效率」场景，统一管理：

| 功能域 | 说明 |
|--------|------|
| 系统信息 | 查看 CPU / 内存 / 硬盘 / 操作系统 / 网络 / 进程 / 端口占用 |
| 大文件管理 | 扫描、分类、搜索电脑上的大文件（视频 / 图片 / 文档等） |
| 广告屏蔽 | 屏蔽软件广告与个性化推荐（浏览器、视频播放器、搜狗 / 百度输入法等） |
| 简历优化 | 基于 STAR 原则优化个人简历（技能 / 工作经历 / 项目经历） |
| 图表生成 | 根据资料生成思维导图 / 流程图 / 审批流程 |

## 2. 系统边界

**做**：本机信息只读展示、本机文件索引与检索、本机 hosts 广告拦截、简历文本结构化、文本转图表。

**不做**（明确排除，避免范围蔓延）：
- 不做跨设备 / 云端同步与账号体系。
- 不做对目标软件的注入、篡改二进制、内存修改（广告屏蔽仅限 hosts 域名层）。
- 不做需要常驻后台的杀毒 / 主动防御。
- 简历与图表默认本地处理，联网 AI 能力仅作为**可选后端**（见 `ARCHITECTURE.md` §5）。

## 3. 技术选型

| 类别 | 选型 | 理由 |
|------|------|------|
| 桌面框架 | Electron 30+ | 跨平台、生态成熟 |
| 构建 | electron-vite | main / preload / renderer 统一 Vite 构建，HMR |
| 前端 | React 18 + TypeScript 5 | 组件化、类型安全 |
| 状态管理 | Zustand | 轻量、无样板代码，适合桌面 |
| 样式 | CSS Modules + 设计令牌 | 作用域隔离、可控 |
| 运行时 | Node.js 20+ | 主进程系统能力 |
| 数据库 | better-sqlite3 | 同步 API、免服务、适合单机 |
| 系统信息 | systeminformation | CPU / 磁盘 / 网络 / 进程一站式 |
| 图表渲染 | mermaid | 文本转图、跨端一致 |
| AI 后端（可选） | 可配置（OpenAI 兼容 / Anthropic） | 简历优化与图表生成的核心能力 |
| 进程管理（主进程） | 内置 `child_process` | 端口反查等系统命令兜底 |

> 完整依赖清单与版本锁定见「实施路线图」阶段 1。

## 4. 总体架构概览

```
┌─────────────────────────── renderer（React + Zustand + CSS Modules）┐
│  页面：系统信息 / 大文件 / 广告屏蔽 / 简历 / 图表                     │
└───────────────────────────────┬─────────────────────────────────────┘
                    contextBridge (window.api) —— 类型化 IPC 契约
┌───────────────────────────────┴─────────────────────────────────────┐
│  preload：暴露类型化 api，无业务逻辑                                  │
└───────────────────────────────┬─────────────────────────────────────┘
                        ipcRenderer.invoke('domain:action')
┌───────────────────────────────┴─────────────────────────────────────┐
│  main（主进程）                                                       │
│   ├─ ipc/        路由到各功能域处理器                                  │
│   ├─ services/   业务逻辑（system / file / adblock / resume / diagram）│
│   ├─ ai/         可选 LLM 后端适配层                                   │
│   └─ db/         better-sqlite3 连接 + repository                     │
└──────────────────────────────────────────────────────────────────────┘
```

原则：**渲染层无 Node 权限**（`contextIsolation: true`、`nodeIntegration: false`），所有系统能力经主进程 + IPC 暴露。

## 5. 目录结构

```
my-pc/
├── src/
│   ├── main/                  # 主进程：窗口、IPC、系统能力、数据访问
│   │   ├── index.ts
│   │   ├── window.ts
│   │   ├── ipc/               # ipcMain.handle 处理器（按功能域分包）
│   │   ├── services/          # 业务逻辑
│   │   ├── ai/                # 可选 LLM 适配层
│   │   └── db/                # 连接、迁移、repository
│   ├── preload/               # contextBridge 类型化 API
│   ├── renderer/              # React 应用
│   │   └── src/{pages,components,stores,styles}
│   └── shared/                # 跨进程共享类型（IPC 契约）
├── docs/                      # 本文档目录
├── .claude/  .ai-rules/       # 技能与规则
├── electron.vite.config.ts
├── package.json  tsconfig*.json
```

## 7. 分阶段实施路线图

> 里程碑按「可运行、可验证」切分，每阶段产出可演示的增量。阶段间有依赖，需串行推进。

### 阶段 0 · 工程脚手架（目标：空壳可启动）
- 初始化 electron-vite + React + TS，配好 `tsconfig`、ESLint、目录结构。
- 跑通 main / preload / renderer 三段与一个最小 IPC 往返（如 `app:ping`）。
- 接入 better-sqlite3，跑通数据库初始化与迁移。
- **验收**：`npm run dev` 打开窗口，渲染层能调用主进程拿到返回值。

### 阶段 1 · 系统信息模块（目标：核心价值闭环）
- 实现 `system-monitor` 模块：概览 / CPU / 内存 / 硬盘 / 网络 / 进程 / 端口反查。
- 落地 `src/shared/types.ts` 类型契约与统一 IPC 封装（`invoke()` + 错误处理）。
- 完成「系统信息」页面与通用组件（信息卡片、表格、进度条）。
- **验收**：页面实时展示本机信息，端口反查能定位占用进程。

### 阶段 2 · 大文件管理模块（目标：持久化 + 检索）
- 实现文件扫描（异步 + 进度）、分类、SQLite 索引、搜索。
- 完成「大文件」页面（列表 / 筛选 / 搜索 / 分类统计）。
- **验收**：扫描出大文件并可分类、搜索；重启后索引仍在。

### 阶段 3 · 广告屏蔽模块（目标：hosts 拦截闭环）
- 实现 hosts 规则管理、备份 / 恢复、管理员权限处理。
- 完成「广告屏蔽」页面（软件分类开关、规则编辑、一键恢复）。
- **验收**：开启屏蔽后目标广告域名被解析到本机，可一键回滚。

### 阶段 4 · AI 集成层（目标：为后两个模块铺路）
- 实现 `ai/` 适配层：可配置后端（OpenAI 兼容 / Anthropic）+ 本地规则兜底。
- 完成「设置」页（API 配置、模型选择、开关）。
- **验收**：配置 API 后能完成一次测试调用；未配置时走本地兜底。

### 阶段 5 · 简历优化模块（目标：STAR 闭环）
- 实现简历数据模型、STAR 改写（AI 优先 / 本地模板兜底）、导入导出。
- 完成「简历优化」页面（技能 / 工作经历 / 项目经历编辑 + 优化）。
- **验收**：输入平淡经历，输出结构化 STAR 描述。

### 阶段 6 · 图表生成模块 + 收尾（目标：完整交付）
- 实现资料 → 结构抽取 → Mermaid 生成与渲染，三类图表（思维导图 / 流程图 / 审批流）。
- 完成「图表生成」页面与 Mermaid 渲染集成。
- 打包发布（electron-builder）、补全 `docs/`、更新技能与规则。
- **验收**：全部 5 个功能域可用，产出可分发的安装包。

> 每个阶段对应一个或多个功能模块，开发前先读 `modules/` 对应文档；技能 `electron-architecture` 始终优先加载。
